# 铸算·华夏纪

《铸算·华夏纪》是一款面向《从零开始构建现代计算机》课程的游戏化教学平台。学生以夏商周为背景，在地图与房间中行走、与 NPC 对话接取任务，在内置的电路编辑器里亲手搭建从晶体管、逻辑门到锁存器的电路，由服务器统一判定对错并记录成绩；教师在后台查看全班进度并导出成绩。

本仓库是平台的整体框架交付，包含账号系统、游戏主循环、章节插件接口、云端存档和教师后台，并附第一章的四个正式电路关卡作为可完整跑通的示例。

## 快速开始

运行环境只需要 Python（3.10 或更高版本）。后端只使用 Python 标准库和 SQLite，不需要安装任何第三方包；前端是原生 JavaScript，不需要构建步骤。

第一次运行前，先创建一个管理员账号。在仓库根目录执行：

```bash
python server.py --init-admin
```

命令会依次提示输入账号、显示名和密码，密码输入时不显示字符是正常现象。创建教师账号的方法相同，把参数换成 `--init-teacher`。

然后启动服务：

```bash
python server.py
```

服务默认监听 `http://127.0.0.1:8765/`，数据库是仓库根目录下的 `game.sqlite3`。需要改地址、端口或数据库位置时，使用 `--host`、`--port`、`--db` 参数。

如果已经有一份准备好的数据库文件，把它命名为 `game.sqlite3` 放到仓库根目录后直接启动即可，其中的账号和数据会原样使用。

学生账号不需要逐个创建。管理员先建立班级，教师再按班级导入学生名册，学生在第一次登录时自行设置密码。名册支持 CSV、TSV 和 XLSX 三种格式，`examples/` 目录里有空白模板和一份示例名册可以参照。

## 使用流程

学生端的完整流程是：登录后进入主界面，在大地图选择章节，在小地图进入地点，在房间里走到 NPC 身边对话并接取任务，然后进入关卡。关卡内是一个电路编辑器，可以拖放元件、连线、随时试算，保存后的电路图存放在服务器上，换一台电脑登录也能继续。正式提交后，服务器当场给出判定结果，成绩可以在个人成绩页查看。

教师登录后进入教师后台，可以按班级查看每名学生的关卡进度和成绩，查看正式电路关卡的逐关结果，并把成绩和电路结果分别导出为 CSV 文件。

管理员负责学校结构和账号本身：建立与归档班级、管理教师与学生账号、处理学生转班和账号纠错。管理员看不到学生的个人成绩，成绩只对教师和学生本人可见。

## 系统结构

| 路径 | 职责 |
|---|---|
| `server.py` | 服务入口与全部 HTTP 接口，零依赖，单文件启动 |
| `database.py` | 数据层：账号、会话、进度、成绩、钱包等全部表结构与读写 |
| `chapters.py` | 章节注册表：章节、地点、任务和关卡清单的定义数据 |
| `quest_model.py` | 任务数据模型的定义与校验 |
| `schemas/` | 任务数据模型的 JSON Schema |
| `level_content.py` | 关卡文件的加载、版本锁定与已发布版本校验 |
| `levels/` | 关卡数据文件，每关一个 JSON，含公开题面与隐藏测试 |
| `circuit_engine.py` | 电路仿真引擎：晶体管级导通求解与门级传播 |
| `circuit_service.py` | 正式关卡的取题、试算、尝试发放与提交判定 |
| `circuit_results.py` | 成绩汇总：学生个人成绩与教师端结果的计算 |
| `management.py` | 教学管理业务层：班级、账号、权限与操作日志 |
| `roster.py` | 学生名册解析，支持 CSV、TSV、XLSX |
| `public/` | 前端页面与脚本，含字体、场景图等全部静态资源 |
| `examples/` | 名册模板与示例文件 |
| `tests/` | Python 单元与接口测试、Node 前端冒烟测试 |
| `tools/` | 素材引用检查、空白数据库生成、100 人压测脚本 |

## 章节与关卡接口

这一部分是框架的核心交付，后续每一章的内容都通过同一套接口接入，接入时不需要修改服务主体代码。

章节在 `chapters.py` 的注册表中声明。每个章节条目包含章节编号、标题、地点、NPC、任务和关卡清单，其中任务按 `quest_model.py` 定义的数据模型书写，并通过 `schemas/quest-model.schema.json` 的格式校验。任务包含步骤、完成条件和奖励，完成条件可以指向正式关卡的服务端成绩。尚未开发的章节把 `implemented` 标为假，接口会明确拒绝在这类章节里开始正式关卡。

玩家进度以章节为单位统一存档。每个学生每一章有一份 JSON 状态，包含任务进度和本章全部电路图，通过同一个进度接口读写。保存时必须带上当前版本号，两个页面同时修改同一份存档时，后保存的一方会收到冲突提示，不会互相覆盖。单章存档上限为 4 MiB。

关卡是 `levels/` 目录下的独立 JSON 文件，与判定代码分离。每个关卡文件带有自己的版本号，学生第一次打开关卡时锁定该版本，之后一直按这一版本判定。已发布版本的关卡文件在服务启动时做哈希校验，内容被改动时服务会拒绝启动；需要修订已发布的关卡时，应另存为新版本文件发布。这样保证同一名学生前后两次提交面对的是同一套题。

关卡文件中的公开题面和隐藏测试是分开的。学生取题时只能拿到公开部分，包括题面、可用元件和公开测试例；隐藏测试向量只存在于服务器，判定在服务器完成。

新增一章的步骤是：在注册表中增加章节条目，按数据模型写好任务，把关卡 JSON 放进 `levels/` 并登记到章节的关卡清单中，最后把房间与地图所需的素材放进 `public/` 并登记。新增一关只需要增加一个关卡 JSON 并登记，不需要改动引擎和判定代码。

## 电路评测

正式关卡的提交只接受电路图本身，客户端附带的任何分数都会被拒绝。服务器用隐藏测试向量逐组判定：组合电路按真值表逐组验证，时序电路按脚本逐步验证。判定反馈包含已通过组数与总组数、第一个未通过的测试组、汇总后的警告信息、本次使用的元件数与该关的最简元件数，以及本次完成用时。用时由服务器在学生打开关卡时开始计时、提交时结算，学生无法自行填报。

成绩分两类记录。正式电路关卡的成绩由服务器判定产生，演示关卡的成绩按演示协议记录，两类在数据中带有不同的标记，在学生和教师的页面上也分开显示。每关的代表成绩取通过组数最高的一次，组数相同时取最近一次；一关一旦判定完成，之后成绩不会被撤销。

学生在某关全部通过后，会获得这一关所用元件的「封装」：例如通过非门关卡后，得到一个可以当作单个元件使用的非门封装，可以在后续关卡中直接放置，封装内部的电路可以查看但不能修改。封装的发放和成绩在同一次提交中完成，不会出现成绩已记录但封装未发放的情况。

学生在学习过程中的行为数据也随成绩一并保存，包括每关的提交次数、每次提交的第一个卡点和完成用时。教师可以在后台查看这些数据，并随成绩一起导出。

任务奖励在任务定义中声明，由服务器发放。奖励包含铜钱和谱系物品两类，同一份奖励只会发放一次，重复保存进度不会重复入账。铜钱目前只做记录和展示，游戏内暂未开放消费入口。

## 数据与账号安全

全部运行数据保存在一个 SQLite 文件中。备份数据只需要复制这个文件，恢复时放回原位置即可。服务重启后，账号、进度、成绩和已发放的封装都保持不变。

密码以 PBKDF2-HMAC-SHA256 加盐存储，迭代 24 万次，数据库中不保存明文密码。登录会话有效期为 7 天。停用账号、归档班级等少数不可逆的管理操作，接口要求额外确认后才执行。

## 测试

提交任何改动之前，请依次运行下面三组检查，并确认全部通过：

```bash
python tools/check_assets.py
python -m unittest discover -s tests -p "test_*.py"
```

前端冒烟测试是 `tests/` 目录下的 `js_*.mjs` 文件，需要 Node.js，逐个用 `node tests/<文件名>` 运行。

在本 README 对应的提交（`8b1531e`）上，106 个 Python 测试和 12 个 Node 冒烟测试全部通过，素材引用检查无断裂。

100 人同时在线的验证使用压测脚本。把使用方式运行一遍即可：

```bash
python tools/loadtest_100.py
```

脚本会自建临时数据库和 100 个学生账号，让每名学生同时完成登录、打开关卡、保存电路 10 次、试算 10 次和正式提交 1 次，最后报告错误数和延迟分布，结束后自动清理临时文件，不影响正式数据库。错误数为 0 即为通过。需要注意的是，100 人在同一秒登录时，密码校验会按设计在 CPU 上排队，登录延迟会明显高于错峰登录，这是算法强度带来的预期现象，不是功能错误。

## 功能对照

本次框架交付对照课程题目的验收点，情况如下：账号系统（注册登录、学生与教师角色、会话保持）、游戏主循环（大地图选章、场景切换、NPC 对话、任务接取与提交）、章节插件接口（章节注册、进度与成绩回传、统一存档格式，并有四个正式关卡证明接口可用）、云端存档（章节完成状态、成绩、电路存档；代码存档与电路共用同一份章节状态，待第三章接入代码类关卡时启用）、教师后台（学生进度查看、成绩导出 CSV）均已实现。演示账号可以完整跑通「登录到教师端可见」的全链路，100 人同时在线有压测脚本和判定方法，主流浏览器以当前版本的 Chrome 与 Edge 为兼容基准。

加分项的现状是：学习行为数据采集已经实现，尝试次数、卡点和用时都随成绩保存；成就系统和排行榜目前是占位页面，尚无真实业务数据；界面基座即本仓库的样式、组件与两款内嵌子集字体，可供后续章节直接复用。

## 当前边界

第一章的地点名称、人物名称和对话台词是框架验证阶段的测试文案，正式剧情由内容组定稿后，按章节接口的数据格式填入，不需要改动代码。第二至四章已经注册为空章节，只有结构，没有关卡内容。大地图与小地图目前使用展示图，地点入口位置以图片归一化坐标配置，正式美术到位后替换图片并调整坐标即可。

两款内嵌字体是按游戏文案裁切的子集，覆盖当前全部用字；今后新增文案如果引入生僻字，需要把新字补进子集后再发布。字体的正式使用授权由团队在对外发布前确认。
